# Little Days · 小日子

一个用英文留住生活的个人日记网页应用。React + TypeScript + Vite，纯前端，无服务器、账号或数据库。

## 本地运行

需要 Node.js 22.12+（推荐 Node.js 24）。

```bash
npm install
npm run dev
```

打开终端显示的地址。开发服务默认允许局域网访问，手机可使用电脑的局域网 IP 和相同端口打开，但手机与电脑不会共享数据。

```bash
npm test
npm run build
npm run preview
```

`dist/` 可以部署到静态托管服务。建议使用 HTTPS；不要通过双击 `index.html` 的 `file://` 地址运行。

## 部署到 GitHub Pages

仓库已包含 GitHub Actions 工作流：推送到 `main` 分支后，会安装依赖、运行测试并构建，然后将 `dist/` 发布到 GitHub Pages。

1. 在 GitHub 仓库的 **Settings → Pages → Build and deployment** 中，将 **Source** 设为 **GitHub Actions**。
2. 将项目提交并推送到 `main`。在仓库的 **Actions** 页面查看 **Deploy to GitHub Pages** 的运行结果。
3. 部署成功后，从 **Settings → Pages** 打开网站。当前仓库的默认地址通常是 `https://xr-su.github.io/note-with-ai/`；实际地址以 GitHub 显示为准。也可以在 Actions 页面选择 `main` 分支手动运行工作流。

无需把 `dist/` 提交到 Git，也无需在仓库中保存 AI 密钥。日记和可选保存的密钥属于浏览器的当前网站来源；从本地开发地址切换到 Pages 后，原记录不会自动出现，请先导出 JSON 备份再导入。浏览器直连模型服务是否可用，仍取决于服务商的跨域策略和网络。

## 功能

- 当天日记：按浏览器本地日期每天一篇，多次打开继续记录。
- 回忆：创建多篇独立经历，标题可编辑。
- 英文问题和中文辅助，一次一个追问。
- 保留中文或英文原文，下方显示英文翻译或纠正；英文纠错附简短中文说明。
- 原文与输入草稿自动保存在浏览器，刷新后可以从历史记录继续。
- 结束并归档时生成英文第一人称总结；保留完整对话，支持再次继续。
- 修改自己的回答后重新生成对应英文，并清除过时总结；后续对话保留。
- 历史记录搜索、模式筛选、整篇删除确认，以及 JSON 备份导出与导入。
- AI 失败、取消或超时后保留原文，支持手动重试，不自动重试付费请求。
- 温暖纸感界面，桌面侧栏、手机记录抽屉，无外部字体或图片 CDN 依赖。

## 配置 AI

打开右上角设置，输入你的 DeepSeek 或 MiniMax 国内平台 API 密钥，选择服务后保存。仅使用这两家国内 HTTPS API，**不调用 OpenAI**。

| 服务 | 国内端点 | 默认模型 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/chat/completions` | `deepseek-flash` |
| MiniMax | `https://api.minimax.cn/v1/chat/completions` | `MiniMax-M3.1-Flash` |

DeepSeek 关闭思考，使用 JSON 模式；MiniMax 使用低思考档位，返回内容在本地校验。首次开场问题为固定双语问题，之后的追问、翻译、纠错及总结使用真实模型，不提供伪造的离线 AI 结果。

价格、估算、选择理由及效果评估方法见 [模型对比](docs/model-comparison.md)，应用设置内也有简要对比。价格核查于 2026-11-13，以官方平台实际账单为准。没有真实密钥，因此**未做授权调用或实际效果排名**。

## 数据与安全

日记存储在当前网站来源的 `localStorage`，不会上传到本应用后端。AI 调用会把**当前篇**必要的对话发送给所选服务处理，其他篇日记和未发送草稿不进入请求。不要输入不希望发送给模型服务的敏感信息。

密钥默认只留在当前页面内存，刷新后需要重新填写。勾选“记住”才会以明文存在浏览器，取消勾选会移除已保存密钥。浏览器同来源脚本可读取本地数据；请使用可信托管环境，不在共享设备上长期保存密钥。导出的备份仅包含日记，不包含密钥。

清除网站数据、换浏览器、换设备、换域名或端口会导致原来的记录不可见或被删除，没有自动同步。请定期导出 JSON 备份。导入按记录 ID 合并；与已有记录 ID 相同或同一天的日记不会覆盖。损坏的存储或导入文件不会被静默覆盖；保存空间不足时，页面内容会保留在内存并显示备份提示。

支持 Web Locks 的浏览器会限制同一网站只有一个标签页可写，其他标签页只读。没有 Web Locks 的环境请只在一个标签页记录；应用能检测存储变化，但不保证此类浏览器中的并发写入安全。Web Locks 通常需要 HTTPS 或 localhost。

由于是浏览器直接请求，模型平台必须允许来自当前网站的跨域访问。如果网络、账户或跨域策略禁止调用，页面会提示错误并保留原文；本应用不会绕过限制或使用未知代理。

## 验证范围

使用 Vitest 和 React Testing Library 验证本地数据、密钥策略、模型请求和 JSON 校验、HTTP 错误、超时、编辑恢复、归档重试草稿保护、继续对话、删除以及多标签页只读保护。所有模型响应测试均为合成响应，不证明真实模型质量或真实浏览器跨域可用性。

依照用户要求，不使用 Playwright 或 Superpowers 进行后续实现与验证。尚未在实际手机浏览器中验证最终弹窗布局；需使用自己的密钥确认网络和模型输出。
