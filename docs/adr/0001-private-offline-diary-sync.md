# 为个人多设备使用增加支持离线的大陆云端日记同步

本方案已被 [口令授权的云端快照同步](0002-passphrase-cloud-snapshot-sync.md) 替代。以下保留此前讨论记录，不代表当前选定方案。

2026-11-23，用户确认第一版仅服务自己的多台设备，保留离线编辑。同一篇日记发生并发修改时保留双方版本供用户选择，避免按设备保存时间直接覆盖而丢失内容。

应用每次打开时自动尝试同步云端内容，并用小图标显示同步状态，以减少在旧版本上继续编辑的机会。启动时显示本地内容并短暂禁止编辑，同步完成后开放编辑，超过约 3 秒可选择继续离线编辑。自动同步不能消除离线或并发编辑冲突。

用户确认邮箱验证码登录后直接看到日记，无需独立解锁口令，并明确接受云端具有解密能力。这取代了讨论初期的“云端运营者无法读取正文”要求：不采用用户自行保管独立解锁口令的端到端加密方案，改用受账号权限保护、云端管理解密能力的方案；具体存储加密配置仍需随服务选型核实。该取舍优先满足新设备登录即可使用和凭邮箱恢复访问的体验。

云端必须能从中国大陆直接访问；具体服务与地域尚未选定。整个访问链路还需考虑前端页面、认证接口、邮件收取与同步接口，不能仅凭服务商名称认定实际网络可用。

## Consequences

现有 JSON 导入不会更新已有日记，不能直接充当同步协议；同步需要识别共同版本和日记删除。不同设备同一天独立创建的当天日记仍应归属于同一个日记，而不是破坏每天一篇的约束。

同步完整日记，包括原始对话、英文纠正、总结、标题、归档状态和未发送草稿；AI API 密钥与日记记忆设置由每台设备单独配置。云端服务、前端托管、存储加密配置和具体同步协议尚未决定。本 ADR 记录已确认的设计方向，不表示同步功能已经实现；现有运行行为仍见 [当前日记设计](../diary-design.md)。

加密约束针对云端同步存储。用户主动调用 AI 时，仍按已有设置向选定模型服务发送必要正文。
