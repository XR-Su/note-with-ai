# Cloud upload platform limits

Researched on 2026-11-23 using official Tencent CloudBase documentation. This note describes published platform behavior for an ordinary event cloud function behind the HTTP gateway and PG-mode storage. It does not establish the deployed account's configuration; see `cloud-upload-current-limits.md` for those verified facts.

| Area | Supported conclusion | Official source |
| --- | --- | --- |
| Ordinary event-function timeout | Default 3 seconds; configurable from 1 to 900 seconds. Exceeding the configured timeout forcibly interrupts execution. HTTP gateway exposure does not change an ordinary event function into the separate HTTP-function type. The HTTP-function range of 1–7200 seconds therefore should not be applied to the current function. | [Function configuration](https://docs.cloudbase.net/cloud-function/function-configuration/config), [HTTP gateway event mapping](https://docs.cloudbase.net/service/access-cloud-function) |
| Function memory | Default 256 MB; published configurable range 64–3072 MB. CPU resources scale with allocated memory. | [Function configuration](https://docs.cloudbase.net/cloud-function/function-configuration/config) |
| HTTP request/event body size | No numeric maximum confirmed from the current CloudBase pages inspected. The gateway passes request information into `event`, including string `body` and `isBase64Encoded`. Do not present a guessed 6 MB or another service's quota as the verified CloudBase gateway limit. | [HTTP gateway event mapping](https://docs.cloudbase.net/service/access-cloud-function) |
| HTTP/function response size | No numeric maximum confirmed from the current CloudBase pages inspected. An application response limit and the platform's accepted response limit are separate constraints. | [HTTP gateway request/response examples](https://docs.cloudbase.net/service/access-cloud-function) |
| PG storage single-object upload size | Controlled by `storage.buckets.file_size_limit`, expressed in bytes. Current docs do not give a universal numeric ceiling or the deployed bucket's value. The documented `20 * 1024 * 1024` SQL setting is an example, not the platform default. Recommended avatar limits of 2–5 MB and public-asset limits of 10–50 MB are recommendations, not hard platform ceilings; private-file limits are “按业务决定”. | [PG limits](https://docs.cloudbase.net/storage/pg/limits), [PG upload constraints](https://docs.cloudbase.net/storage/pg/upload) |
| PG storage access path | PG uploads use Storage API → COS, with metadata coordinated by Storage API. Uploads also depend on bucket MIME rules and INSERT/UPDATE RLS policies. These storage constraints are distinct from a request that first passes through the ordinary event function. | [Storage modes](https://docs.cloudbase.net/storage/introduce), [PG upload constraints](https://docs.cloudbase.net/storage/pg/upload) |
| Gateway route frequency | Route thresholds can be configured from 100 QPS up to the environment maximum. Client thresholds can be configured from 0 to 30 QPS, identified by UserID or ClientIP. These are configuration ranges, not proof of currently configured thresholds. | [HTTP gateway rate limits](https://docs.cloudbase.net/service/rate-limit) |
| Default-domain frequency restrictions | No numeric default-domain abuse threshold is published in the current page. CloudBase monitors traffic and may prohibit access after abnormal traffic. Current docs say compliant use no longer has a hard expiry ban; default domains remain intended for development/testing. A custom domain avoids the default-domain risk-control policy. | [Default-domain restrictions](https://docs.cloudbase.net/service/alias) |
| Default-domain browser behavior | Browser navigation (`Sec-Fetch-Mode: navigate`) receives a confirmation interstitial. Other requests receive `Content-Disposition: attachment`. Confirmation-cookie lifetime is dynamically adjusted. A custom domain must have ICP filing according to the linked documentation. | [Default-domain restrictions](https://docs.cloudbase.net/service/alias) |

## Evidence boundaries

- The previously suggested URL <https://docs.cloudbase.net/cloud-function/limits> returned the site's 404 page during this research. Its historic limits were not treated as current verified values.
- The official Tencent SCF quota page <https://cloud.tencent.com/document/product/583/11637> did not return readable quota content through this retrieval; no numeric size claim is based on it.
- No cloud resources were changed and no real uploads, quota-boundary requests, or provider calls were made. Bucket limits, environment QPS, deployed timeout, and account entitlements require separate account evidence.
- A bucket allowing a large object does not prove the existing function-proxy route can carry it. The deployed function timeout, application payload validation, gateway/event payload ceiling, and PG bucket rules all need to be satisfied by that route.
